# JSON 상태 저장·로드 벤치마크

측정일은 2026-08-13이며, Apple Silicon Mac의 macOS 26.5.2와
Python 3.9.6에서 힌트·점수 히스토리가 포함된 v2 스키마로 실행했습니다.
각 항목을 11회 측정한 중앙값과
nearest-rank 방식의 p95이며,
저장은 임시 파일을 완전히 쓴 뒤 `state.json`으로 교체하는 현재 코드를
그대로 사용했습니다. 로드 피크 메모리는 `tracemalloc`이 측정한 Python
할당량이므로 프로세스 전체 메모리와는 다를 수 있습니다.

```bash
python3 scripts/benchmark_state.py --sizes 10 100 1000 5000 --repeats 11
```

| 퀴즈 수 | JSON (KiB) | 저장 중앙 (ms) | 저장 p95 (ms) | 로드 중앙 (ms) | 로드 p95 (ms) | 로드 피크 (MiB) |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 10 | 2.6 | 0.32 | 0.47 | 0.18 | 0.25 | 0.02 |
| 100 | 25.7 | 0.94 | 1.03 | 1.00 | 1.10 | 0.14 |
| 1,000 | 255.9 | 6.66 | 7.53 | 9.42 | 9.90 | 1.28 |
| 5,000 | 1,279.4 | 32.44 | 34.19 | 48.23 | 49.53 | 6.34 |

이 환경에서 1,000개는 로드·저장 p95가 각각 10ms 안쪽이어서 개인용
콘솔 프로그램의 현재 JSON 구조를 유지해도 됩니다. 다만 결과는 장비,
디스크, Python 버전, 실제 문자열 크기에 따라 달라지므로 절대적 보장치가
아닙니다.

이 프로젝트의 전환 검토 기준은 다음과 같습니다.

- 대표 운영 데이터에서 시작 또는 저장의 p95가 100ms를 반복해서 넘음
- 상태 파일이 10MiB를 넘거나 전체 재저장이 사용자 대기로 느껴짐
- 사용자가 퀴즈를 조건으로 반복 검색하거나 일부 행만 자주 수정함
- 두 개 이상의 프로세스가 동시에 읽고 쓰는 요구가 생김

첫 번째 단계에서는 고유 ID·카테고리 인덱스와 페이지네이션을 도입하고,
부분 수정·동시성이 필요하면 SQLite 행 단위 저장과 트랜잭션으로
전환합니다. 전환 전에는 이 스크립트로 같은 장비와 데이터에서 다시
측정합니다.
